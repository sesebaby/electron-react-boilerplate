# 最终细化重构方案

## 📊 深度分析总结

基于对代码的深入分析和架构适合性评估，我们确定了最优的重构方案。

### 关键发现
1. **业务特点**：进销存是高度集成的业务，产品、库存、交易密切相关
2. **使用模式**：80%的调用集中在产品CRUD和库存操作
3. **数据流复杂**：组件需要同时访问多种相关数据
4. **缓存确实过度**：10个Map缓存对小型应用完全没必要

### 架构决策
**采用领域驱动设计**，按业务领域拆分，而非技术层面过度拆分。

## 🎯 最终架构方案

### 新架构设计
```
UI组件 → 领域服务 → 直接IPC调用 → SQLite
```

### 服务拆分方案
```
InventoryService (1613行) → 3个领域服务 (150-400行/个)
```

| 服务 | 职责 | 代码行数 | 核心功能 |
|------|------|---------|---------|
| **InventoryDomainService** | 库存领域核心 | 400行 | 产品+库存一体化管理，事务处理 |
| **MasterDataService** | 基础数据管理 | 200行 | 分类、单位、仓库等基础数据 |
| **ReportService** | 报表统计服务 | 150行 | 统计信息、报表数据、预警 |

### 架构优势对比

| 指标 | 原架构 | 6服务方案 | 领域服务方案 ✅ |
|------|-------|----------|----------------|
| 服务数量 | 1个巨型 | 6个小服务 | 3个领域服务 |
| 代码行数 | 1613行 | 200-300行/个 | 400+200+150行 |
| 服务间耦合 | 无 | 高 | 低 |
| 事务处理 | 复杂 | 困难 | 简单 |
| 学习成本 | 高 | 中 | 低 |
| 维护成本 | 高 | 中 | 低 |
| 业务完整性 | 差 | 分散 | 好 |

## 🛠️ 技术实现细节

### 1. InventoryDomainService（400行）

**核心职责**：
- 产品和库存的一体化管理
- 库存事务处理（入库、出库、调整）
- 保证数据一致性

**关键方法**：
```typescript

// 库存操作（事务性）
async stockIn(request: StockOperationRequest): Promise<DomainServiceResult<StockTransaction>>;
async stockOut(request: StockOperationRequest): Promise<DomainServiceResult<StockTransaction>>;

// 产品管理
async createProduct(product: CreateProductRequest): Promise<DomainServiceResult<Product>>;
async updateProduct(id: string, updates: UpdateProductRequest): Promise<DomainServiceResult<Product>>;

// 业务查询
async getLowStockItems(): Promise<DomainServiceResult<ProductWithStock[]>>;

// 向后兼容方法
async getProducts(filter?: any): Promise<DomainServiceResult<{ items: ProductWithStock[] }>>;
async updateStock(productId: string, warehouseId: string, quantity: number, type: string): Promise<DomainServiceResult<any>>;
```

**事务处理示例**：
```typescript
private async executeStockOperation(request: StockOperationRequest, type: TransactionType): Promise<DomainServiceResult<InventoryTransaction>> {
  try {
    await window.electronAPI.dbBeginTransaction();
    
    // 1. 验证产品和仓库存在
    // 2. 获取当前库存
    // 3. 计算新库存数量
    // 4. 更新库存
    // 5. 创建交易记录
    
    await window.electronAPI.dbCommitTransaction();
    return { success: true, data: transaction };
  } catch (error) {
    await window.electronAPI.dbRollbackTransaction();
    throw error;
  }
}
```

### 4. DomainServiceManager（100行）

**核心职责**：
- 简化的服务管理
- 无复杂依赖注入
- 向后兼容支持

```typescript
export class DomainServiceManager {
  private _inventoryDomainService: InventoryDomainService;
  private _masterDataService: MasterDataService;
  private _reportService: ReportService;

  constructor() {
    // 直接实例化，无复杂初始化
    this._inventoryDomainService = new InventoryDomainService();
    this._masterDataService = new MasterDataService();
    this._reportService = new ReportService();
  }

  getInventoryDomainService(): InventoryDomainService { return this._inventoryDomainService; }
  getMasterDataService(): MasterDataService { return this._masterDataService; }
  getReportService(): ReportService { return this._reportService; }
}

// 向后兼容适配器
export class ServiceManagerAdapter {
  getInventoryService(): InventoryDomainService {
    return domainServiceManager.getInventoryDomainService();
  }
}

export const serviceManager = new ServiceManagerAdapter();
```

### 业务完整性保证
- **事务一致性**：库存操作在领域服务内部处理事务
- **数据完整性**：单一服务管理相关数据，避免不一致
- **业务逻辑集中**：相关业务逻辑在同一服务内，易于维护
- **向后兼容**：适配器保证现有组件无缝迁移
